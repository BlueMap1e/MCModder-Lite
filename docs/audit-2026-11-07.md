## 0. 结论摘要

1. **削减方向正确，但 4 项编辑效率功能属于“连带被删”**：预编辑、改动列表批量对比、紧凑审核界面、日志日期直填。不建议立刻恢复，先列入候选清单，按真实需求逐个评估。
2. **上游不是“私货多”，而是“范围大 + 依赖重 + 维护面广”**：它仍在 `dev` 上开发新功能（封面高斯模糊、弹窗方向等），且保留 4 个安装期远程 `@require`、Supabase 云层、three/opentype/GIF/ECharts。对一个注入每个页面的脚本，这是实打实的失败面。
3. **Lite 的“轻量”主要体现在失败面，不是体积**：源码/设置减少约 32%，但未压缩产物只从 ~2.97 MB 降到 ~2.48 MB（约 -16%），因为 Vue/CodeMirror/DOMPurify 仍在。真正的体积杠杆是“按宿主拆分”，不是继续删功能。
4. **当前最该立即修的是 6 个 P1**：图片本地化提示的 HTML 缺引号、两处裸 `fetch`、设置不即时生效且无提示、后台定时器未清理、`HomePageInit` 原地 `reverse()`、若干未判空的 `.get(0)`。
5. **最大性能风险是社群夜间的全文档观察者**：`main.ts` 的 `cleanBbsElements` 在每次任意 DOM 变更时全文档重扫并写内联样式。建议去抖 + 只处理新增节点，改动前必须真机 bbs 验收。
6. **namespace 迁移的“持久说明面”还没对齐**：CHANGELOG 与 release notes 已写清“删除旧条目重装、设置需重配”，但 README 仍承诺“自动升级、设置与数据保留”，而停留在 lite.8 的用户通常只会看 README/GF/社群帖。见 O-01。

**给复核者的建议**：优先核对 F-01（缺引号是否真会导致提示丢失）、F-05（缓存引用是否确为同一数组）、F-03/F-07 的影响是否被高估，以及 O-01 对 README 与触达面的判断是否成立；其余项多为排期/卫生问题，可按优先级取舍。

### 1.1 代码范围

### 1.2 方法

1. **静态阅读 + 定向检索**：配置键与读取方交叉检查；`Init` 的 `canRun()` 门控；观察者/定时器/事件监听生命周期；HTML 拼接与 URL 写入点；死模块引用分析。
2. **动态探针**（Playwright + GM 垫片，参考 `scripts/smoke-public.mjs` 的注入方式，未入库）：
   - 在真实 mcmod.cn 页面注入 `dist/mcmodder-lite.user.js`，收集 `pageerror` / `console.error`；
   - 覆盖：首页、模组列表、贡献榜、`/tools/`、`/tools/cbcreator/`、`/tools/tctool/`；
   - 记录宿主 jQuery 版本、脚本注入耗时、标记类与按钮挂载情况。
3. **上游对照**：`git fetch upstream` 后比对源码规模、设置项、依赖、`@require`、页面覆盖与近期提交。

### 1.3 未覆盖范围（重要）

- **无登录态**：编辑器、个人中心、后台审核、留言板、社群发帖等需要登录的路径没有实机验证；相关结论来自代码阅读或维护者既有记录。
- **非篡改猴沙箱**：探针用 GM 垫片模拟 API，没有 Xray、HttpOnly cookie、跨标签页同步；涉及这些的结论需真机复核。
- **未做 CPU/内存 profile**：性能结论以代码结构 + 注入耗时为主，bbs 观察者的触发频率是推断，需真机测量。
- **未逐条审计 CSS**：约 190 KB 的样式表只做了规则级抽查（功能标记类、`:has`/`@property`），没有做全量覆盖审计。

### 2.2 上游是否“私货过多、过于臃肿”？

**判断：不能简单定性为“私货”，但确实“过重”，而且重在与定位不匹配。**

- 上游的娱乐/社交/云端功能不是零星彩蛋，而是成体系的模块：Supabase 自定义表态、闪光贡献、用户徽章、成就、GIF 编辑器、结构编辑器（three/opentype）、ECharts 面板、跨标签页广播/请求队列。被 Lite 删掉的功能目录合计约 5.2k 行（占上游源码约 10%），此外还有大量相关 init 与 Vue 组件。
- 更关键的是**运行形态**：这是一个在所有 `*.mcmod.cn` 页面注入的脚本，却承担云服务、3D、图片编解码、社交通知等职责，并依赖 4 个安装期远程脚本。对普通读者/编辑者，这些依赖带来的失败模式（CDN 不可达、云服务异常、跨域、体积）远多于收益。
- 上游仍在积极开发新功能，这本身不是缺点；它只是服务于另一群用户（重度编辑/愿意配置云服务的玩家）。**两个项目的定位分叉是真实且合理的，不需要合并。**

### 2.3 Lite 的削减是否过于激进？

**判断：约八成正确，四项属于“连带被删”，可以复议但不急。**

删得对（不建议恢复）：

| 功能                                       | 理由                                                    |
| ------------------------------------------ | ------------------------------------------------------- |
| Supabase 云端表态/闪光/徽章                | 需要账号与云服务，失败面与隐私成本高                    |
| 多账号切换                                 | 半死功能，浏览器 profile/容器更合适（已在 AGENTS 固化） |
| GIF 编辑器、结构编辑器、ECharts 面板、成就 | 与“夜间 + 编审”定位无关，且引入重依赖                   |
| 请求队列、跨标签页弹窗/请求提示            | 为已删除功能服务，维护成本 > 收益                       |
| JSON 管理面板                              | 已保留自动链接面板里的“导入 JSON”入口，够用             |
| GTCEu、网络监控、Live2D、愚人节彩蛋        | 低价值/高维护                                           |

削得偏激进（候选恢复清单，按建议顺序）：

| 功能                                   | 价值                   | 风险/成本                                          | 建议                                   |
| -------------------------------------- | ---------------------- | -------------------------------------------------- | -------------------------------------- |
| 预编辑（锁定资料先编辑、解锁自动提交） | 对真正的编辑者是硬功能 | 依赖定时任务 + GenericTable + 倒计时组件，交互复杂 | **优先评估**；若要恢复，先设计最小实现 |
| 紧凑化审核界面                         | 审核页信息密度         | 纯前端布局，成本低                                 | 可作为可选开关恢复                     |
| 改动列表批量对比                       | 审核效率               | 依赖 diff 组件（已保留）                           | 中等成本，看使用频率                   |
| 日志搬运日期直填                       | 高频小便利             | 很轻                                               | 顺手可做                               |

> 重要认知：**代码 -32% ≠ 体积 -32%**。库（Vue/CodeMirror/DOMPurify 等）是固定成本，删功能主要减少的是应用代码与失败面。若目标是低端设备启动速度，优先考虑按宿主拆分；若目标是“更少的坏路径”，当前路线正确。

### 3.2 P1：正确性 / 功能

#### F-01｜图片本地化提示的 HTML 缺半个引号

- **证据**：`src/widget/MainText.ts:133`
  ```ts
  `<span class="badge badge-warning mcmodder-localize-check>该图片尚未本地化，但是体积 (...) 超过了本地图床最大体积限制</span>`;
  ```
  `class="..."` 没有闭合引号，`>` 被吞进属性值，整段提示文本会被解析坏。
- **触发条件**：开启“图像本地化检测”（默认关）+ 图片非本地化 + 体积超过图床上限。
- **影响**：用户只看到边框颜色，看不到具体原因；控制台无报错，属静默显示错误。
- **建议**：补 `"`；顺手给该分支加一条渲染级断言（或截图回归）。
- **验证**：静态确认；默认关闭，故线上影响面小。

#### F-02｜两处裸 `fetch` 绕开 `createRequest`

- **证据**：
  - `src/widget/MainText.ts:123`：`fetch(src, { method: "HEAD" })`，只有 `.then`，没有 `.catch`；跨域图片会被 CORS 拒绝，产生未处理 Promise（被 `main.ts` 的全局 `unhandledrejection` 记一条错误）。
  - `src/Utils.ts:417`：`imageURL2base64` 直接 `fetch(url)` 读 blob。
- **影响**：绕过 `minimumRequestInterval` 限速、请求日志、统一错误提示；`HEAD` 失败时图像检测静默缺失；与 AGENTS 的“所有网络流量走 `Utils.createRequest`”硬约定冲突。
- **建议**：改用 `createRequest`（`method: "HEAD"` 可用；blob 场景用 `responseType: "blob"`），至少补 `.catch` 并记录一次去抖后的警告。
- **验证**：静态确认；触发依赖“图像本地化检测”开启。

#### F-03｜多数设置不即时生效，设置面板也没有提示

- **证据**：
  - 全局只有 3 个设置 watcher：`nightMode`、`nightModePreference`、`preferredWiderScreen`（`src/Mcmodder.ts:618-627`）。
  - 外观样式在 `StyleLoader.run()` 里一次性拼装并注入（`src/loader/StyleLoader.ts:577`），仓库内没有 `location.reload`。
  - 设置写入通过 `getSettingsWritableRef` 持久化，但读取方大多在 `run()`/构造期只读一次。
- **影响**：在个人中心（SPA）修改主题色、字体、渐变、表格主题、功能开关后，当前页没有变化；用户容易判定“设置坏了”。离开 center 回主站会整页重载，所以问题主要在 center 内与“改完立刻看效果”的场景。
- **建议**：短期在设置页加一句“部分设置刷新页面后生效”，并提供“立即刷新”按钮；中期只对少量低风险外观键（主题色、字体、渐变）做 live-apply。注意 `Utils.addStyle` 无 id 时会重复注入，live-apply 需先给样式标签固定 id 并替换内容。
- **验证**：静态确认（watcher 数量、无 reload 调用）。

#### F-04｜后台“自动查询待审项”关闭后定时器仍在跑

- **证据**：`src/init/admin/AdminVerifyInit.ts:185-197`
  ```ts
  const interval = this.configs.getSettings("alwaysNotifyVerification") ?? 0;
  if (interval > 0.1) {
    clearInterval(this.notifyTimer);
    this.notifyTimer = window.setInterval(...);
  }
  ```
  `clearInterval` 只在“启用”分支里；把设置改成 ≤0.1 后，旧 interval 会继续到页面卸载。
- **影响**：后台页持续空转/发请求；后台 SPA 导航重复进入时也会保留旧定时器。
- **建议**：进入 `run()` 先无条件 `clearInterval(this.notifyTimer)`，再按需重设。
- **验证**：静态确认；需 admin 登录态实测。

#### F-05｜`reverse()` 原地修改缓存的设置数组

- **证据**：`src/init/HomePageInit.ts:39`
  ```ts
  const recentlyVisitedMods = this.configs.getSettings("recentlyVisitedMods")?.reverse() ?? [];
  ```
  `mcmodderSettings` 是 `StorageBuffer` 缓存的活对象，`getSettings` 返回的是同一数组引用；`reverse()` 会污染同页后续读取。
- **影响**：同页后续读取会看到反转后的顺序，属于确定的状态污染；当前写入路径多用 `filter` 产生新数组，故持久化风险较低，但不应依赖这个巧合。
- **建议**：`[...(arr ?? [])].reverse()`。
- **验证**：静态确认（缓存实现见 `src/StorageBuffer.ts`、`src/config/ConfigRepository.ts`）。

#### F-06｜未判空的 `.get(0)` 会在站点 DOM 变动时中断 init

- **证据**（均在页面/结构满足时才走到，但都没有兜底）：
  - `src/init/VerifyPageInit.ts:118`：`d.find("i").get(0).classList`
  - `src/init/admin/AdminVerifyInit.ts:373`：`.get(0).firstChild as Text`
  - `src/ueditor/AdvancedUEditor.ts:277`：`editToolButton.get(0).lastChild`
  - `src/ueditor/UEditor.ts:440`：`this.$body.children().last().get(0).getBoundingClientRect()`
- **影响**：站点改版/空编辑器/空审核项时抛 `TypeError`，该 `init` 后半段静默不执行；主循环虽然有 per-init try/catch，但错误只进控制台，用户看到的是“功能没了”。
- **建议**：统一用可选链 + 早退；按 AGENTS 的“可能永久生效的跳过要重试或显式记录”，至少 `console.warn` 一次。不要用空 `catch` 吞掉。

### 3.3 P2：性能

#### F-07｜社群夜间 `cleanBbsElements` 是当前最大的性能隐患

- **证据**：`src/main.ts:140-183`
  - 观察 `document.body` 的 `{ childList: true, subtree: true }`；
  - 每次任意 DOM 变更执行：整页 `querySelectorAll`（`.tl .ts th, ...`）、整页属性选择器扫描（`tr[style*="background"], ...`）、给命中元素写内联样式；
  - 另外 0/100/500/1000 ms 各跑一次。
- **影响**：Discuz 页面懒加载图片、广告、AJAX 通知频繁，观察者可能每秒触发多次；每次都是全文档扫描 + 样式写入，长帖子页可能出现滚动/输入卡顿，且与“夜间模式”强绑定。
- **建议**：优先用 `requestAnimationFrame` 或 100–200 ms 去抖合并；只处理 `mutation.addedNodes` 子树；把“整页首扫”留到首次/`load`。改动必须真机 bbs（登录态、长帖、夜间）验收，避免漏掉动态插入的表格/单元格。
- **验证**：代码结构确认；触发频率未实测。

#### F-08｜启动成本与“全量包在所有宿主执行”

- **证据**：探针在 lite.8 构建（1.52 MB）上测得注入并执行约 **156–179 ms**（首页/模组列表/贡献榜，headless Chromium，本机，未做 4x CPU 降速）；lite.9 构建为 1.54 MB，量级相同。社群页只跑夜间分支、工具页只需要一个 marker，但静态 import 让整包都被求值。
- **影响**：每个页面都有百毫秒级主线程占用；低端设备更明显；工具页/社群页为少量功能支付全量成本。
- **建议**：短期把“启动耗时”纳入发版观测（4x CPU 降速）；中期评估按宿主拆分/动态加载。注意 AGENTS 已把“拆包”列为需计划的 deferred 项，不要在修 bug 时顺手做。
- **验证**：已实测（注入耗时），非 profile。

#### F-09｜个人中心图表的观察者与复检定时器叠加

- **证据**：`src/init/CenterInit.ts:81-100`：每次 `run()` 新建 2 个 document 级 `MutationObserver`（`_echarts_instance_` 与 `class`），夜间应用后再排 4 个 `setTimeout` 复检。
- **影响**：只在 center 生效，量不大；但属于“每轮 apply 再排 4 个 timer”的链式调度，站点频繁重绘时会产生多余回调。
- **建议**：复检改为递增次数上限（如最多 3 轮）；观察者可在图表稳定后断开，路由切换时重建。
- **验证**：静态确认。

#### F-10｜center 编辑器观察者可能常驻整个会话

- **证据**：`src/Mcmodder.ts:821` 在 center 域无条件 `observe(document.body, { childList: true, subtree: true })`，匹配到 `_iframeholder` 后 disconnect；若页面始终没有编辑器，则常驻。
- **影响**：每次 DOM 变更执行一次正则 + id 检查，CPU 很低；但属于 AGENTS 明确关注的“会话级文档观察者”，长会话/复杂 SPA 页应尽量收敛。
- **建议**：保留 center 无条件的正确性（这是 2026-11-06 的回归修复，不能退回静态门控）；可加“路由变化后重新评估/超时后降级为低频轮询”，并记录一次跳过原因。
- **验证**：静态确认；AGENTS 已记录例外。

#### F-11｜每秒一次的调度轮询

- **证据**：`src/loader/ScheduleRequestLoader.ts:29` `setInterval(() => list.check(), 1e3)`；`check()` 读缓存的 `scheduleRequestList` 并过滤。
- **影响**：开销很小（数组通常为空），但每个页面（含 bbs/center/tools）都有一次/秒的唤醒，不利于空闲/省电。
- **建议**：按“最近一条待办的到期时间”安排下一次 `setTimeout`；没有待办时不排 timer（任务创建时再唤醒）。
- **验证**：静态确认。

#### F-12｜正文内联样式两遍 `getComputedStyle`

- **证据**：`src/Mcmodder.ts:732-762`，在 `disableAutoStyleFix` 为 false（默认）时，对 `textArea.find("[style]")` 连续两遍：一遍查 `background-color`，一遍查 `color`；`.css()` 会取计算样式。
- **影响**：长正文（大量 UEditor 内联样式）启动时多一遍样式解析/回流；已有 `[style]` 预过滤，符合 AGENTS，但可以合并成单遍。
- **建议**：一次遍历同时读两个属性；只在确实存在 `[style]` 时执行。
- **验证**：静态确认。

### 3.4 P3：兼容性 / 健壮性

- **F-13｜宿主 jQuery 1.7.2–2.1.0 混用**：探针实测首页 1.8.2、`/tools/cbcreator/` 1.7.2、模组列表/贡献榜 2.1.0。工具页现已挂载完整脚本，未来任何 >1.7 的 jQuery API 只会在部分宿主炸（`:first-child()` 笔误事件即此类）。建议把“共享代码 jQuery 基线 1.7”写进 AGENTS，并新增工具页/首页 smoke。**当前注入探针 0 pageerror。**

## 5. 方向建议（lite.9 之后）

### 5.1 定位与边界

保持“轻量、稳定、零外部依赖的百科夜间与编审辅助”。建议在 README 固化三块：

1. **支持矩阵**：Zen/Firefox（主测）+ Chromium；覆盖 www / bbs / center / tools；admin 需权限账号、标注“未完整验证”。
2. **非目标**：不做账号体系/云同步、不做娱乐功能、不合并上游、不做大重构。
3. **版本节奏**：功能冻结；每 2–4 周一个 patch，小批量可归因（自动更新没有回滚通道）。

### 5.2 发布流程

- lite.9 已发布（含 namespace 变更），当前有一笔未推送的 `npm run pack` 工具提交（`001f471`）；推送前先确认 README/GF 的迁移说明已同步（O-01），再进入下一轮。
- `npm run pack` 已解决“版本号不同步 → 空 notes”的一半问题；建议再补一条 CHANGELOG 小节存在性校验（可放在 pack 或 CI）。
- CI 的 `smoke-public` 有环境性超时（首页 30s），release job 又不依赖 smoke。保持“失败可重跑”没问题，但发版前人工确认 night / bbs / tools 三条路径。

### 5.3 质量门（按投入产出排序）

| 优先级 | 门禁                                                                     | 价值                       | 成本                                   |
| ------ | ------------------------------------------------------------------------ | -------------------------- | -------------------------------------- |
| 1      | 工具页 smoke（`/tools/`、`/tools/cbcreator/`、`/tools/tctool/`）         | 覆盖 jQuery 1.7 与全量挂载 | 低（复用现有 harness，已探针验证可行） |
| 2      | 设置覆盖检查（Settings + ConfigLoader → 断言每个 key 有读取方）          | 永久堵住“死开关”回归       | 低                                     |
| 3      | CHANGELOG/版本一致性检查                                                 | 防空 release notes         | 低                                     |
| 4      | 纯函数单测（Vitest：escapeHTML/safeURL/parseItemFullName/颜色/版本比较） | 保护安全工具函数           | 低                                     |
| 5      | 包体积预算（压缩产物 < 1.6 MB，未压缩 < 2.6 MB）                         | 防缓慢膨胀                 | 低                                     |

### 5.4 修复顺序建议

**第一批（下个补丁，低风险）**：F-01、F-04、F-05、F-06、F-02（收口）、F-03（加提示）+ O-01（README/GF 同步）。
**第二批（需真机验收）**：F-07（bbs 观察者去抖）、F-12（合并样式遍历）、F-16。
**第三批（排期/评估）**：F-08（启动成本与拆包评估）、F-09、F-10、F-11。
**保持不动**：死代码清理、大文件拆分、按宿主拆包（没有计划前不做）。

### 5.5 社区与维护者习惯

- 用户少时，**响应速度与发布说明就是口碑**；release notes 写“用户能感知的变化”，不写 commit 列表。
